## 概念卡 7：堆内存纪律

**是什么**：堆是 malloc 借、free 还，借多少还多少、谁借谁还；每一条 malloc/realloc 都要有一条配对的 free 路径，包括所有提前 return 的错误分支。
**为什么**：堆的生命周期由程序员手动管。不 free 就泄漏（长时间运行的嵌入式程序会耗尽内存），free 后还用是 use-after-free，free 两次直接崩；而且工具只在"崩了/越界了"时才报，抓不住那些没崩但结果错的逻辑 bug。
**我代码里的位置**：`parts/03_dynbuf/dynbuf.c` 的 `dynbuf_append`（realloc 结果先进临时指针 `new_data`，判空后才写回 `b->data`）、`dynbuf_free`；`parts/08_rewrite_list/list.c` 的 `append_to_tail`（malloc 后判 NULL）和 `free_all`。
**易错点**：malloc 后不判 NULL 直接写（"分配→检查→使用"三拍子少一拍）；直接 `b->data = realloc(b->data, n)`，失败时原指针被覆盖、原数据全丢；错误分支提前 return 忘了 free 已经分配的内存；`dynbuf_free` 后没把 data 置 NULL，留下悬空指针。
**面试追问**：
- 问：为什么 realloc 一定要用一个临时指针接？
  答：realloc 失败返回 NULL 且不会释放原块。直接写回原变量等于把原指针丢了——内存泄掉、数据再也找不回来。先接临时再判空，失败时原数据依然有效，调用方能安全回退。
- 问：malloc(0) 和 free(NULL) 合法吗？
  答：free(NULL) 是合法的空操作；malloc(0) 的返回值是实现定义的（可能返回一个非 NULL 但不可解引用的指针）。所以自己的初始化函数要用显式的 `data = NULL / cap = 0` 表示空态，别靠 malloc(0)。
