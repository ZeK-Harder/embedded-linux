## 概念卡 9：环形缓冲区

**是什么**：环形缓冲区用一块定长内存加读写下标，靠取模实现绕回：`idx = (idx + 1) % cap`，走到末尾就回到开头，空间反复复用而不搬数据。
**为什么**：串口/网络是"生产者写、消费者读"，用环形缓冲不需要 memmove，一次写入就是 O(1)；定长分配也符合嵌入式不该动态扩张的要求。
**我代码里的位置**：`parts/05_ringbuf/ringbuf.h` 的 `struct ringbuf { data, cap, read, write, count }`；`parts/05_ringbuf/ringbuf.c` 的 `ringbuf_write/ringbuf_read`（先用 space/avail 截断 n，再逐字节取模前进）、`ringbuf_space = cap - count`。
**易错点**：空/满判据两套方案别混用——本代码用 count 计数，cap 可以全部用满；若不用 count 而只看下标，就必须留一格空位，判满要写成 `(write + 1) % cap == read`，漏掉取模就会在绕回边界失效——cap=8、write=7、read=0 时明明满，式子算出 `8 == 0` 反而不成立；而 read == write 又既像空又像满，没法区分。部分写语义没处理——write 只能写进 space 个字节、read 只能取出 avail 个，必须返回真实数量，不能当全部成功。
**面试追问**：
- 问：判空判满有哪两套方案？
  答：一是额外用 count 计数（就是本卡代码），空是 count==0、满是 count==cap，容量全用满；二是不用 count、只看下标，read==write 判空，判满要先算出绕回后的下一格：`(write + 1) % cap == read`，取模不能省，否则 write 停在末格时判不出来；代价是永远浪费一格。
- 问：`ringbuf_write` 只能写进去一半，算失败吗？
  答：既不算失败也不算全部完成，这叫部分写。返回值就是实际写入字节数，调用方要拿它和 n 比，差多少下次重传；把部分写当全部成功是丢数据最常见的来源。
